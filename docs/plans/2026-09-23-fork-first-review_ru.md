# Ревью fork-first: плагин session 0.18.0 против спецификации

Дата: 2026-09-23. Охват: репозиторий `claude-session` на `8c035cb` (чистое дерево), установленный плагин на Mac и на VM (`ssh claude-vm`), пользовательские скилы и агенты на обеих машинах, проектные workflow в `.claude/workflows/`. Эталон: `reviews/claude_fork_first_architecture_full_dialogue.md` (разделы спецификации 1, 4-6, 9-15, 17; её собственные решения обозначены «spec D05») и `docs/plans/2026-09-22-fork-first-decisions.md` (решения плагина обозначены «plan D1»-«plan D16»), плюс правило пользователя от 2026-09-23: любой запуск субагента, кроме форка, идёт через workflow, потому что `Agent` не умеет задавать effort.

Сырые находки дали три прохода ревью: A (скилы base, ask, codex и ping, хуки, `lib/classes.json`), B (девять агентов-помощников, `session:helper`, `session:batch`, проектные workflow, `lib/block.src.js`, четыре пользовательских агента), C (установки на Mac и VM, пользовательские скилы). Дубликаты ниже слиты; у каждого пункта указаны исходные id. Шесть пунктов высокой важности перед написанием документа перепроверены по файлам.

Не сделано: тесты не запускались (`tests/plugin/all.sh`, `bin/build.sh --check`), живого прогона маршрутизации не было, `permissions.deny` харнесса не читался.

## 1. Запускает ли base помощников перед форками, и действует ли правило «всё, кроме форка, через workflow»?

В тексте — да. Жёсткое правило 3 (`plugins/session/skills/base/SKILL.md:13`) говорит, что main запускает помощника до форка, а раздел «Launching a helper» (`SKILL.md:112`, `:162`) допускает ровно две формы: форк через `Agent`, помощник через `Workflow` `session:helper` или `session:batch`. Обычные субагенты через `Agent` стоят в списке Forbidden.

На практике маршрут через помощника почти не срабатывает:

- Контракты аргументов `session:helper` и `session:batch` не дошли до main при старте сессии (R-2). Main видит правила классов и слотов, но не аргументы `helper`, `ask`, `in`, `out`, `codex`, `cwd`.
- Сценарию B нужно, чтобы операция была «ясна из запроса», а base не даёт ни положительных, ни отрицательных примеров-триггеров (R-3). Сценарий A, `session:batch` и `HELPER WANTED:` ни разу не запускались вживую (plan D12).
- В этой сессии ревью main запустил четыре форка и ни одного помощника — ожидаемый исход при текущем тексте.
- Правило «только через workflow» ничем технически не обеспечено (R-1): девять типов помощников `session:*` и четыре пользовательских агента остаются в реестре `Agent`, и прямой запуск идёт на модели и effort сессии без всякого признака.
- Никто не проверил, что `agent()` внутри workflow действительно применяет переданный `effort` (R-7). А именно ради управления effort и нужна обёртка workflow.

## 2. Несут ли агенты, скилы и workflow реальную методику?

В основном да. Оценки:

| объект | оценка | примечание |
|---|---|---|
| finder | хорошо | названные инструменты (grep, find, git grep, `git log -S`), ранжирование, раздел сомнительного, покрытие |
| extractor | хорошо | источник на каждое утверждение, противоречия отдельно, покрытие; нет правила выборки для очень большого материала |
| web-extractor | хорошо | лимит 8 загрузок, URL плюс фрагмент плюс версия плюс дата на каждый факт |
| runner | хорошо | `commands.txt` с кодами выхода, логи, окружение, остановка на первом шаге, который нельзя выполнить, никогда не чинит |
| applier | хорошо | точный образец, исключения перечислены, одна финальная проверка; нет патча или списка изменённых файлов (R-20) |
| consumer | хорошо | запись шагов, первый блокер; ничего не сказано об изоляции от репозитория |
| checker | тонко | правила охвата ясны, но нет процедуры чтения (сначала перечислить случаи, потом проверить каждый) и нет инструмента поиска |
| breaker | хорошо | гипотезы, журнал попыток, минимальное воспроизведение дважды, бюджет |
| codex | хорошо | полный контракт заголовка, точная команда, опрос, коды ошибок |
| guide (встроенный) | пусто для этого протокола | ничего не знает о `result.md` и трёх строках возврата (R-24) |
| `session:helper` | хорошо | ячейка из таблицы, разбор тройки, неизвестный статус — `failed`; пробелы R-11, R-16 |
| `session:batch` | хорошо | одна строка на элемент, пустой возврат — строка `failed`, уникальные каталоги |
| `memory-gc` | хорошая методика, сломанный протокол | R-4, R-13, R-27 |
| `skill-author` | хорошая методика, старый протокол | R-13 |
| `test-session` | хорошее разделение drive/judge, дефект ожидания, старый протокол | R-5, R-13 |
| пользовательские агенты session-driver, skill-author, skill-reviewer, transcript-analyst | хорошо | жёстко задают model и effort во frontmatter (R-14) |
| скил base | методика есть, но для main её слишком много | R-10 |
