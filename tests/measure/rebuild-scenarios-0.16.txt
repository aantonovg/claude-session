# Behavior scenarios of the 0.16 rebuild (tmux, one fresh session per scenario).
# Driver: VARIANT=<base|gate|...> tests/rebuild/scenario-run.sh [<key> ...], environment built by
# tests/rebuild/scenario-env.sh (real HOME, scratch project, claude --plugin-dir on the worktree
# plugin). The judge of .claude/workflows/test-session.js reads the run's <key>.jsonl and records
# the verdict with `scenario-run.sh --verdict <key> PASS|FAIL`; a part's Test reads it only through
# tests/rebuild/verdicts.sh <variant>:<key>.
# Format, free text, no id inside a test name:
#     <key>  prompts: "first" "second"
#         base: <arguments of /session:base, or (none)>
#         setup: <one shell line, run inside the scratch project>
#         finish: <prompt index> <how many workflow finish notices that prompt waits for>
#         PASS: <the rule the judge applies>
# `finish` keeps a prompt that reads a result from racing the launch it reads: the runner sends
# that prompt only after the transcript holds that many workflow finish notices. A scenario that
# reads a result twice carries one `finish` line per such prompt; after a `/clear` the count starts
# at the notices of the new transcript, because the clear starts one.
# Every field but the key and the prompts sits on its own indented line: the reader of
# scenario-run.sh matches `^\s*<name>:`, so a field on the head line would never be read. The
# prompts are the quoted strings after `prompts:`, so no other field may carry a double quote.
# Keys live here only; no test name carries one.
